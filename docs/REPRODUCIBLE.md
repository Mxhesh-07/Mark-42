# Reproducible environment (G7)

The project is pinned to exact versions with `requirements.txt` and `requirements-dev.txt`.
These are the single source of truth for runtime and CI. They can be installed with pip directly.

## Quick start (standard)

```bash
python -m venv .venv
source .venv/bin/activate  # on Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt
pip install -r requirements-dev.txt  # optional, for testing/linting
python main.py
```

## Lockfiles

Lockfiles guarantee byte-for-byte reproducibility across machines and CI. The repo ships
pinned `==` requirements; two lockfile formats are offered so the choice of tooling
doesn't block reproducibility.

- `uv.lock` — generated by [uv](https://github.com/astral-sh/uv). uv is extremely fast
  and deterministic; it can install directly from the lock.
- `requirements.lock` — a fully-pinned, hash-verified lock generated by `pip-compile`
  (from `pip-tools`). Works with vanilla pip and matches the existing requirements
  split.

If you add or upgrade a dependency, update the input `requirements*.txt` files and
regenerate the corresponding lock(s).

### Generate with uv

```bash
# Install uv if needed: curl -LsSf https://astral.sh/uv/install.sh | sh
uv pip compile requirements.txt -o uv.lock
uv pip compile requirements-dev.txt -o requirements-dev.lock  # optional
```

Install from the lock:

```bash
uv pip sync uv.lock  # or pip install -r uv.lock
```

### Generate with pip-tools

```bash
pip install pip-tools
pip-compile --generate-hashes requirements.txt -o requirements.lock
pip-compile --generate-hashes requirements-dev.txt -o requirements-dev.lock
```

Install from the lock:

```bash
pip install --require-hashes -r requirements.lock
```

## Python build

The application is run **from source** (see `setup.py`), not distributed as an
installable wheel in this repo. For packaging (E1), see `agent/build.py` which
produces a frozen onedir bundle via PyInstaller. The build identity is tracked by
`agent/version.py` (reads `[project] version` from `pyproject.toml`).

- Python version: tested on 3.10 and 3.12 (see CI matrix). 3.10 is the minimum
  targeted version (`pyproject.toml` uses `target-version = "py310"` for ruff).
- The dependencies that require native builds (e.g. `pyaudio`) are pinned to
  versions known to build on Windows and Linux in CI.
- No editable install is required for development; running `python main.py` from the
  repo root works as-is.
